| Term | Acronym | Definition |
| :---- | :---- | :---- |
| *Agreement Request* |  | The request by a *Confederate Organization* to use a *Cross-Border E-Service*. |
| *Application Programming Interface* | API | An interface that allows different software to communicate with each other, exchanging data and functionality. |
| *Confederate Organization* |  | A public or private organization which has completed the identification process (onboarding) on the *Knode* to which it belongs based on territorial, administrative, or organizational competence. |
| *Consumer Knode* |  | The *Consumer*’s *Knode*. |
| *Consumer* |  | A *Confederate Organization* that uses a *Cross-Border E-Service*. |
| *Cross-Border E-Service* |  | An *E-Service* enabled by the *Producer* for *cross-border interactions*. |
| *Cross-border interaction* |  | A digital interaction performed by subjects belonging to distinct *Knodia Domains*, performed to ensure the exchange of data or integration of services. |
| *Electronic Archiving* |  | As defined in the *eIDAS Regulation*. |
| *Electronic seals* |  | As defined in the *eIDAS Regulation*. |
| *European Interoperability Framework* | *EIF* | As defined in the *Interoperable Europe Act*. |
| *Innovation measures* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperability assessment* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperability Node* | *Knode* | The component of *Knodia* to enable *cross-border interactions*. |
| *Interoperability regulatory sandbox* |  | A controlled environment established by a European Union entity or a public body for the development, training, testing, and validation regarding innovative interoperability solutions, where appropriate in real-world conditions, supporting the cross-border interoperability of trans-European digital public services for a limited period of time under regulatory supervision. |
| *Interoperability solutions* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperable Europe Agenda* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperable Europe Board* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperable Europe Community* |  | As defined in the *Interoperable Europe Act*. |
| *Interoperable Europe portal* |  | As defined in the *Interoperable Europe Act*. |
| * Knode-to-Knode API* | K2K API | The machine-to-machine APIs implemented and used by the *Knodes* to engage in the communication protocols of *Knodia*. |
| *Knodia Attribute* |  | The attributes defined in *Knodia* that are associated with *Confederate Organizations* and used to grant the right to make requests for access to *Cross-Border E-Services*. |
| *Knodia Category* |  | The categories defined in *Knodia* that are used by *Confederate Organizations* to classify their *Cross-Border E-Services* in relation to the nature of the data and services they provide. |
| *Knodia Domain* |  | A set of subjects that have defined and shared common rules, based on mutual trust, to proceed with the sharing of data and services among themselves using digital tools. |
| *Lawfulness of processing* |  | As defined in the *GDPR*. |
| *Modello di interoperabilità* | *ModI* | The interoperability model adopted by Italian public administrations. |
| *Monitoring and evaluation* |  | As defined in the *Interoperable Europe Act*. |
| *National competent authorities and single points of contact* |  | As defined in the *Interoperable Europe Act*. |
| *Operator* |  | A natural person associated with a *Confederate Organization* who uses the functionalities made available by the *Knodes*. |
| *Peer review* |  | As defined in the *Interoperable Europe Act*. |
| *Piattaforma Digitale Nazionale Dati* | *PDND* | The platform provided for in the *ModI* to authenticate and authorize access to *Cross-Border E-Services*. |
| *Policy implementation support projects* |  | As defined in the *Interoperable Europe Act*. |
| *Porta di Dominio* | *PdD* | The component provided for in the *SPCoop* instantiated by individual public administrations to enable machine-to-machine interaction. |
| *Producer Knode* |  | The *Producer*’s *Knode*. |
| *Producer* |  | A *Confederate Organization* that makes *Cross-Border E-Services* available. |
| *Provide-Data* |  | The method of sending data from *Producer* to *Consumer* via a *Cross-Border E-Service*. In this mode, the *Confederate Organization* acquiring new data from the transactions performed is the *Consumer*. |
| *Purpose Statement* |  | The statement made by a *Consumer* to explicitly state the lawfulness of processing under the *GDPR*. |
| *Purpose* |  | The reference to a *Purpose Statement* made by a *Consumer*. |
| *Receive-Data* |  | The method of sending data from *Consumer* to *Producer* via a *Cross-Border E-Service*. In this mode, the *Confederate Organization* acquiring new data from the transactions performed is the *Producer*. |
| *Servizi di Interoperabilità, Cooperazione ed Accesso* | *SICA* | The system that implements and makes available the infrastructural services of *SPCoop*. |
| *Signal Hub* |  | The digital tool provided by the *Knodes* to the *Confederate Organizations* of *Knodia* to distribute data changes of interest to *Confederate Organizations*. |
| *Sistema pubblico di cooperazione* | *SPCoop* | The application cooperation system adopted by Italian public administrations. |
| *Storing* |  | The digital recording performed by an IT system to secure the information necessary for its operations. |
| *Trans-European digital public service* |  | As defined in the *Interoperable Europe Act*. |
