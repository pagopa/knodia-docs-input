An *E-Service Template* standardizes creation of *Cross-Border E-Services* for recurring use cases. If many *Producers* need to provide *Cross-Border E-Services* following the same specification, one *Producer* may create an *E-Service Template* and publish it on its *Knode*. The template is then available for use by other *Confederate Organizations* that need to produce similar *Cross-Border E-Services*.

Every *Producer* can view the *E-Service Templates* available on both its own and other *Knodes*. It can create a *Cross-Border E-Service* by instantiating one such template. The *E-Service* so created inherits all predefined fields from its template, including the specification of the application programming interface (API). However, the creator of the template can specify fields that the *Producer* can override when instantiating the template.

*E-Service Templates*, like *Cross-Border E-Services*, can have multiple versions. When a new version is created, the previous versions are automatically deprecated. New instances can only be created from the latest version. However, *E-Services* can still exist which have been instantiated from an older version. The *Knode* must notify (possibly via other *Knodes*) the *Producers* that have instantiated an *E-Service Template* when a new version of the template is published and (if it is the case) that the version currently in use will no longer be available after a given date.

The *Knodia Consortium* referred to in § [Considerations on the governance of Knodia](./05-11-00_federation-governance.md), capitalizing on the effects of the proposed experimentation, defines in detail how to implement this functionality.
